**产物**：**未重新打包**。`dist/start.exe` 仍是 26.10.31.2313（63,521,549 字节，23:16:11）；

### 现象

用户 11-05 日志（另一台电脑，跑 26.10.31.2253）里出现 4 次
「连续 3 次页面内容没有变化，结束本课程（避免死循环）」，两账号在
14:35:14/14:35:51、16:42:05/16:42:08 几乎同时触发。
页面其实一直在正常前进：诊断 URL 的 `chapterId` 每次不同（…717→…577→…699 / …719），
视频也一节节播完；16:42 的「页面卡住」截图是一张**还没开始播放的全新视频页**。
详细证据见工作区 `课程被结束_根因分析_2026-11-05.md`。

### 根因

1. `main.py:_content_signature()` 的指纹 = `prev_title | 完成点数 | 任务点数 | iframe src 前 80 字符`。
   新版学习页 `.prev_title` 取不到（恒空），所有视频模块 src 前 80 字符都是
   `.../ananas/modules/video/index.html?v=2026-1030-1154` → **所有视频页指纹完全相同**，
   且指纹里没有 URL / chapterId / objectId 这些真正能区分章节的东西。
2. `run()` 只在指纹「不同」时清零 `no_progress`；「该页面无法识别」分支完全不碰计数，
   于是计数能跨 38 分钟、跨多个章节累积（13:53 → 14:31 → 14:35）。
3. 达到 `STUCK_LIMIT` 后 `return 'done'`（= 正常学完），而 `main()` 只对 `'lost'` 重进课程，
   `'done'` 直接关掉课程页切回个人空间 → 用户看到「课程被结束」。

### 改动（`main.py`，只动这一处逻辑）

1. 新增 `_page_identity(driver)` + `_PAGE_IDENTITY_KEYS`：从顶层 URL 与各 iframe src 里提取
   `chapterId / courseId / clazzId / knowledgeId / objectId / jobId / cardId` 作为「页面身份」；
   **不收** `s=` / `ktoken=` 这类每次请求都可能变的随机 token（否则刷新会被误判成换页）。
   取不到稳定参数时返回空串，自动退回原来的内容指纹行为。
2. `run()` 的复合指纹改为 `'身份||内容指纹'`；日志里「第 N 次仍停留在同一页」现在带 chapterId，便于定位。
3. 「该页面无法识别」分支重置 `no_progress` 与 `last_sig`（认不出的页面本身就说明页面变了）。
4. 达到 `STUCK_LIMIT` 不再直接结束课程：先打印诊断 + 存截图 + `driver.refresh()` 重试一次；
   刷新后身份/内容变了就清零计数继续学；仍卡住才 `return 'lost'`，交给已有的
   `_reenter_course()` 回课程页重新定位任务点（最多 3 次）。
